# Implementation decisions (M8)

The M8 spec (`docs/specs/m8-c4-drift.md`) is precise about the mechanics
of `scripts/c4_drift.py` but leaves several concrete choices to the
implementation. Recorded here rather than guessed silently.

- **Every container in the model gets the `Deployable` tag.** The spec
  says "every container that is a cloud resource or a Kubernetes
  workload" - checked container by container (§4 of the spec, all four
  software systems), every single one of the 29 containers in
  `workspace.dsl` is either an AWS/Azure Terraform resource or a
  Kubernetes workload. There is no purely conceptual container at this
  level (those live one level down, as Components inside `triage.worker`,
  which the drift check never touches). So `Deployable` ended up on all
  29, and `docs/c4/drift-allow.yaml` carries the five genuine exceptions
  (below) rather than the DSL under-tagging to dodge them.
- **The join key is the DSL identifier, not the display Name.** The spec
  says so explicitly ("use the identifier"), and Terraform's
  `c4_container` tags already matched it (`ledgerQueue`, `sloReporter`,
  `openBanking`, ...). Helm's `nordwind.dev/c4-container` label did not -
  M6/M6a's own spec wording said the label should carry `<service>`, and
  the chart implemented that as the kebab-case service/image name
  (`cards-authorization`, `open-banking-api`), which can never equal a
  Structurizr identifier like `openBanking` (illegal DNS-1123 characters
  aside, it's simply a different, longer name). Fixed by splitting the
  label's value from the object name: `values.yaml` services gained a
  `c4Container` field (`cards`, `fraud`, `openBanking`), the
  `alerts-bridge`/`kafka-relay` templates' `dict` literals gained
  `c4Container` too, and `_helpers.tpl` stamps that instead of `.name`.
  The k8s object names, image names, Secret names and `KAFKA_USER` values
  are untouched - only the one label's value changed. The Kafka custom
  resource (`templates/kafka/kafka.yaml`) also gained the label directly
  (`nordwind.dev/c4-container: kafka`) since it's the one Strimzi
  resource this chart itself renders.
- **`docs/c4/drift-allow.yaml`'s five entries, and why each is real
  drift-check noise rather than a bug to fix:**
  - `dashboard` - `aws_cloudwatch_dashboard` has no `tags` argument in
    the AWS provider; there is no resource to tag.
  - `appInsights` - tagged `monitor` (shared with Log Analytics, the
    storage account and the service plan) per `infra/README.md`'s
    existing documented convention, not its own `appInsights` tag.
  - `kafkaExporter` - generated by the Strimzi operator from the Kafka
    CR's `spec.kafkaExporter` stanza; this chart renders the CR, not the
    Deployment Strimzi creates from it.
  - `prometheus`, `alertmanager` - provisioned by the separate
    `kube-prometheus-stack` Helm release, not
    `deploy/helm/nordwind-bank`, which is the only chart the spec scopes
    the Helm set to.
- **`--strict` gates on a skipped Helm set, not on anything else.**
  Requirement 1 already defines the two exit-1 conditions unconditionally
  (Terraform/Helm reference an undeclared container; a `Deployable`
  container is in neither); those apply whether or not `--strict` is
  passed. `--strict` only additionally fails the run if `helm` wasn't on
  PATH, which the spec's "skip the Helm set with a warning" line implies
  is otherwise just a warning - `ci.yml`'s `c4` job installs `helm`, so
  `--strict` there is a guard against silently losing Helm coverage, not
  a stricter drift policy.
- **`docs/adr/README.md`'s regeneration is a sibling script,
  `scripts/adr_index.py`**, per the spec's explicit "or a sibling
  `scripts/adr_index.py`" option - it parses every `docs/adr/NNNN-*.md`
  file's `# NNNN. Title` heading rather than extending `c4_render.py`,
  which is Structurizr-export-specific and has no reason to know about
  ADRs.
- **`docs/DESIGN.md` v2.1 → v2.2's actual drift, found while cross-checking
  §4 against the generated views**: §4.2's C4Container diagram never
  gained the `ops` topic or `slo-reporter` boxes M9a added to the real
  model, and §10 still described the drift check as reading
  `terraform show -json` / `helm list -o json` - exactly the live-state
  approach this spec's own non-requirements rule out. Both fixed; no
  container was ever renamed, so nothing else in §4 needed a fix.
