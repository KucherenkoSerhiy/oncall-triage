# Spec: M9 - hardening and operations: self-observability + SLO, DLQ alarm, known-issues export, Route 53 DNSSEC + query logging, environment-scoped OIDC subjects, runbooks, rollback drill, README demo script

Builds on everything M2-M8 (spine on AWS, Azure estate, kind estate, C4 drift). Repository conventions unchanged; all offline gates must pass. Budget stays: the additions here are CloudWatch alarms/dashboard (free tier), one KMS key for DNSSEC (~$1/month - the one deliberate cost increase, flagged in the cost model), an S3 export (cents), a Log Analytics query, and two IAM/Entra changes that need a human credential once (called out).

## Requirements

1. Self-observability, `infra/aws/observability.tf`: CloudWatch dashboard `nordwind-triage-demo` (ingest invocations/errors/p95, SQS age + DLQ depth, worker duration/errors/throttles, API 4xx/5xx, daily LLM spend from the cap table) and four alarms into a new SNS topic `ops` (e-mail subscription to `var.budget_email`): ingest 5xx ratio > 5 % over 5 min, worker errors >= 3 over 15 min, SQS DLQ depth >= 1, worker p95 duration > 60 s. An SLO doc (`docs/slo.md`): "95 % of alerts get a verdict within 5 minutes", measured from `received_at` to `verdict_at` by a scheduled Lambda `slo-reporter` (daily, 128 MB) that writes one line to CloudWatch Logs Insights-friendly JSON and a custom metric `VerdictLatencyP95`; the dashboard shows it.
2. Daily LLM cap and DLQ handling: the cap already exists (M3a `DailyCap`) - add the alarm on `CapReached` and a `bankops replay-dlq` command (move DLQ messages back with a 10-message limit and a confirmation flag).
3. Known-issues export: weekly EventBridge rule -> Lambda `known-issues-export` writes `known-issues-<date>.json` to a private S3 bucket (30-day lifecycle) so the taught memory survives a table wipe; `bankops known-issues import <file>` is the inverse.
4. Route 53 DNSSEC: KMS key (ECC_NIST_P256, `SIGN_VERIFY`, alias `alias/nordwind-triage-dnssec`, us-east-1 as Route 53 requires), `aws_route53_key_signing_key` + `aws_route53_hosted_zone_dnssec` on the delegated zone, and the DS record published at the parent through the existing Cloudflare provider (`cloudflare_dns_record` type `DS`). Query logging: `aws_route53_query_log` to a CloudWatch log group in us-east-1, 7-day retention. Runbook step: `dig +dnssec triage.serhiykucherenko.dev` validates (`ad` flag) - recorded in the PR.
5. Environment-scoped OIDC subjects: PR plans move from the `pull_request` subject to `environment:plan` on both clouds (GitHub `plan` environment with no reviewers, `deploy.yml` plan jobs declare it), the bootstrap trust policies drop `pull_request:*` (AWS) and the `pull_request` federated credential (Azure) so checkov CKV_AZURE_249 needs no skip. This step changes `infra/bootstrap/*` and therefore needs a human credential once; the PR ships the code, the README documents the two commands (`terraform apply` in each bootstrap root with a fresh IAM-user key / `az login`), and the deploy workflow is only switched after the owner confirms the applies ran.
6. Runbooks, `docs/runbooks/`: `triage-spine.md` (ingest 5xx, queue backing up, worker cap reached, verdicts missing, DLQ replay), `deploy-and-rollback.md` (the rollback drill: redeploy `sha-<previous>` from the Actions UI, verify with `bankops`, redeploy forward; record one real drill with timestamps and the run links), `secrets-rotation.md` (console token, HMAC secret, Anthropic key, Cloudflare token, function key - what breaks in between and in which order to rotate), `cost.md` (where each dollar goes, the budgets, how to read Cost Explorer, what to destroy first).
7. README: a 5-minute demo script ("open the console, fire `bankops chaos payments --mode pool`, watch the verdict, then `fraud-lag` over Kafka, then `broker-down` via route B"), the architecture picture links, the "what a reviewer should look at" section (tests, drift gate, runbooks, ADRs), the cost table with actuals from the first month.
8. Tests: `slo-reporter` and `known-issues-export` handlers with moto; `bankops replay-dlq` and `known-issues import` with monkeypatched clients; Terraform gates on the changed roots; checkov clean with the CKV_AZURE_249 skip removed.
9. Diagrams: `workspace.dsl` adds `ops topic`, `dashboard`, `slo-reporter`, `known-issues bucket`; the deployment view shows the DNSSEC key; regenerate; drift gate green.

## Non-requirements

Multi-region, WAF, PagerDuty/Slack delivery, SSO for the console, AKS, cost anomaly detection beyond the budgets.
