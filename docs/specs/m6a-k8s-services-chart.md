# Spec: M6a - Kubernetes bank services, the `nordwind-bank` Helm chart, PrometheusRules, kube-prometheus-stack values, and the helm / kubeconform / trivy CI gates

Slice 1 of 2 of `docs/specs/m6-kind-estate.md` (M6b = kind cluster, Taskfile estate tasks, `estate-demo.yml`, runbook). Builds on M2 (`services/ingest/adapters/alertmanager.py`: label `service` names the service, `severity` critical/high/warning -> sev1/2/3, a receiver name containing `kafka` marks route A; everything here is route B), M5a (`bank/azure/alert_forwarder` accepts Alertmanager webhooks - its function URL is the chart value `forwarder.url`), M4 (fault modes as a pattern). Repository conventions unchanged; all offline gates must pass. New Python dependency: `prometheus_client`. New CI tools (pinned versions, installed in the job): `helm`, `kubeconform`, `trivy`. Nothing here needs a cluster: `helm template` + schema validation is the gate; M6b brings kind.

## Requirements

1. Services, `bank/k8s/<service>/` for `cards_authorization`, `fraud_scoring`, `open_banking_api`: one small Python 3.12 HTTP app each on port 8080 built on `http.server` + `prometheus_client` (`/healthz` -> 200 `ok`, `/metrics` -> Prometheus exposition, `/work` -> performs one unit of work and returns JSON) plus an in-process ticker thread that calls the work function once per second so metrics move without external load. Fault mode comes from `bank/k8s/_shared/faults.py`: `FaultFile(path="/etc/nordwind/fault", ttl=5)` re-reads the file at most every 5 s; empty / missing file = normal; unknown mode = normal with one warning log. Shared: `bank/k8s/_shared/{faults.py, ticker.py, server.py, metrics.py}`; each service imports `_shared` the same relative-path-safe way M5a used for the Azure apps.
   - cards-authorization: histogram `cards_auth_request_seconds` (buckets up to 5 s), counter `cards_auth_requests_total{result="ok|error"}`. `timeouts` -> observe 3.0 s (do not actually sleep 3 s in the ticker; observe the value) and result `ok`; `issuer-down` -> every request `result="error"`.
   - fraud-scoring: histogram `fraud_score_bucket` (buckets 0.1..1.0), counter `fraud_scored_total`. Normal scores ~ N(0.2, 0.05) clipped to [0, 1]; `model-drift` -> N(0.8, 0.05); `latency` -> also observe 2.0 s in a `fraud_scoring_seconds` histogram; `crashloop` -> after 10 s in that mode call `sys.exit(1)` (the Deployment restarts it); `lag` -> accepted, no-op (M7).
   - open-banking-api: counter `openbanking_responses_total{code="200|429"}`, gauge `openbanking_cert_expiry_seconds` (default now + 90 days). `rate-limit-storm` -> 80 % of work units count as `429`; `cert-expiry` -> gauge = now + 3 days.
   One `Dockerfile` per service (`python:3.12-slim`, non-root user, `HEALTHCHECK` on `/healthz`, image entrypoint `python -m <package>`), all buildable from the repo root with `docker build -f bank/k8s/<service>/Dockerfile .`.
2. Helm chart `deploy/helm/nordwind-bank/` (`Chart.yaml` apiVersion v2, version 0.1.0): per service a Deployment (1 replica, image `nordwind/<service>:{{ .Values.imageTag }}` with `imagePullPolicy: IfNotPresent` so `kind load` works, requests 50m/64Mi, limits 200m/128Mi, liveness + readiness on `/healthz`, `securityContext` runAsNonRoot + readOnlyRootFilesystem + drop ALL + seccomp RuntimeDefault, the faults ConfigMap mounted at `/etc/nordwind`), a Service (8080), a `ServiceMonitor` (release label `release: monitoring` so kube-prometheus-stack picks it up - or the selectors in requirement 3 are opened, pick one and document), labels `app.kubernetes.io/name`, `app.kubernetes.io/part-of: nordwind-bank`, `nordwind.dev/c4-container: <service>`. One ConfigMap `nordwind-faults` with keys `cards-authorization`, `fraud-scoring`, `open-banking-api` (empty strings by default) projected as one file per key so each pod reads `/etc/nordwind/fault` from its own key (use `items` + `path: fault` per Deployment). One `PrometheusRule` `nordwind-bank` with group `nordwind-bank.rules` and these rules, each with labels `service`, `severity` and annotations `summary`, `description`: `CardsAuthHighLatency` (`histogram_quantile(0.99, sum(rate(cards_auth_request_seconds_bucket[2m])) by (le)) > 1` for 2m, high), `CardsAuthErrorRatio` (error ratio over 2m > 0.5 for 2m, critical), `FraudScoreDrift` (mean score over 3m > 0.6 for 3m, high), `FraudScoringCrashLoop` (`increase(kube_pod_container_status_restarts_total{container="fraud-scoring"}[10m]) > 2`, high), `OpenBankingRateLimitStorm` (429 ratio over 2m > 0.5 for 2m, warning), `OpenBankingCertExpiringSoon` (`openbanking_cert_expiry_seconds - time() < 14*24*3600`, warning). Values: `imageTag`, `forwarder.url` (default empty), `kafka.enabled` (default false, unused until M7), `monitoring.release`.
3. `deploy/helm/values/kube-prometheus-stack.yaml` for the upstream chart (pin the chart version in a comment and in M6b's Taskfile): Grafana disabled, Alertmanager enabled, `prometheus.prometheusSpec.scrapeInterval: 15s`, `ruleSelectorNilUsesHelmValues: false`, `serviceMonitorSelectorNilUsesHelmValues: false`, Alertmanager config with `group_wait: 10s`, `group_interval: 30s`, `repeat_interval: 1h`, one route to receiver `route-b-forwarder`. Because upstream values cannot read our chart's values, the forwarder URL is injected at install time: the chart renders a Secret `alertmanager-nordwind-config`? No - keep it simple and documented: the Alertmanager config lives in the upstream values file with the URL as a placeholder `__FORWARDER_URL__`, and `task estate-up` (M6b) substitutes it with `envsubst`-style replacement before `helm upgrade`. When the URL is empty the receiver must still be valid YAML (a `webhook_configs` list with a dummy `http://127.0.0.1:9/` URL and a comment). Provide `scripts/render_alertmanager_values.py` (stdlib) that does the substitution and is unit-tested.
4. CI: `ci.yml` gains a `helm` job: `helm lint deploy/helm/nordwind-bank`, `helm template ... | kubeconform -strict -summary -kubernetes-version 1.31.0 -schema-location default -schema-location 'https://raw.githubusercontent.com/datreeio/CRDs-catalog/main/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json'` (for ServiceMonitor / PrometheusRule) with default values and with `--set forwarder.url=https://example/x`, and `trivy config --exit-code 1 --severity HIGH,CRITICAL` on the rendered manifests. The python job picks up the new tests automatically. Add `task helm-lint` and `task helm-check` to the Taskfile.
5. Tests, `tests/bank/k8s/`: `FaultFile` (missing, empty, unknown mode, TTL with injected clock, hot reload), each service's work function per mode using a fresh `CollectorRegistry` (assert the counters/histograms/gauge values), the crashloop exit after the deadline (monkeypatch `sys.exit` and the clock), `render_alertmanager_values.py` substitution incl. the empty-URL case, and a `helm template` golden test that parses the rendered YAML and asserts the six rule names, their `service` labels and that every Deployment has `readOnlyRootFilesystem: true` (skipped when `helm` is not on PATH; CI has it).
6. Docs: `deploy/helm/nordwind-bank/README.md` (values table, how faults reach pods, how rules map to services and severities, what M6b adds), `docs/DESIGN.md` section 3: the three Kubernetes services "M6a code / M6b cluster". C4 stays for M6b (one regenerate for the whole estate).

## Non-requirements

kind, Taskfile estate tasks, `estate-demo.yml`, runbooks, Kafka, Grafana, Ingress, any live cluster in tests.
