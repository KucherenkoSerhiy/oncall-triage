# Spec: M7a - Strimzi (KRaft) Kafka in the chart, topics + SCRAM users/ACLs, producers and consumers in the three services, the `lag` fault, the `broker-down` chaos action, Redpanda contract tests

Slice 1 of 2 of `docs/specs/m7-kafka-backbone.md` (M7b = `alerts-bridge`, `kafka-relay`, Alertmanager routing, Kafka alert rules, the two new scenarios). Builds on M6a (`bank/k8s/*` services + `_shared`, `deploy/helm/nordwind-bank`, `deploy/helm/values/kube-prometheus-stack.yaml`) and M6b (`task estate-up`, `scripts/estate_status.py`, `scripts/chaos_k8s.py`, `estate-demo.yml`, the fault table shared by `bankops` and `chaos_k8s`). Repository conventions unchanged; all offline gates must pass; the `helm` CI job (lint, kubeconform, trivy) must keep passing with `kafka.enabled=true` and `false`. New Python dependency: `confluent-kafka` (use it everywhere; no `aiokafka`). Contract tests use `testcontainers[kafka]` with the `redpandadata/redpanda` image and are skipped when Docker is unavailable (CI has Docker; add a `contract` job that runs them). Nothing here costs money.

## Requirements

1. Operator: `deploy/helm/values/strimzi.yaml` for the upstream `strimzi-kafka-operator` chart (pin the version in `Taskfile.yml` `vars:`), watching only the `bank` namespace, resources trimmed for kind (operator 256 Mi). `task estate-up` installs it into namespace `kafka` after kube-prometheus-stack and waits for the operator deployment to be Available before installing `nordwind-bank`; `task estate-down` unchanged.
2. Chart, behind `kafka.enabled` (default **true** from this slice on; `helm template --set kafka.enabled=false` must still render a working non-Kafka estate): `templates/kafka/` with a `KafkaNodePool` (`dual-role`, 1 replica, ephemeral storage, 768 Mi memory limit, 500m CPU limit) and a `Kafka` (KRaft annotations, version pinned to what the pinned Strimzi supports, listener `tls` on 9093 with `scram-sha-512`, `authorization.type: simple`, `metricsConfig` referencing a ConfigMap `kafka-metrics` with the Strimzi example JMX exporter rules trimmed to broker + topic metrics, `kafkaExporter` enabled with `groupRegex: ".*"` / `topicRegex: ".*"`); `KafkaTopic`s `card.authorized`, `fraud.scored`, `alerts.raw` (1 partition, 1 replica, `retention.ms` 86400000); `KafkaUser`s `cards-authorization` (Write on `card.authorized`), `fraud-scoring` (Read `card.authorized`, Write `fraud.scored`, group `fraud-scoring`), `open-banking-api` (Read `fraud.scored`, group `open-banking-api`), `alerts-bridge` (Write `alerts.raw`), `kafka-relay` (Read `alerts.raw`, group `kafka-relay`) - each with `simple` ACLs scoped exactly to those resources and Describe where the client library needs it; a `PodMonitor` for the Kafka pods and the kafka-exporter so Prometheus scrapes `kafka_consumergroup_lag`. Deployments mount the user Secret (password) and the cluster CA Secret and get env `KAFKA_BOOTSTRAP` (`<release>-kafka-bootstrap.bank.svc:9093`), `KAFKA_USER`, `KAFKA_PASSWORD_FILE`, `KAFKA_CA_FILE`; when `kafka.enabled=false` none of that is rendered and the services run as in M6.
3. Service wiring, `bank/k8s/_shared/kafka.py`: `KafkaSettings.from_env()` (returns `None` when `KAFKA_BOOTSTRAP` is unset), `make_producer(settings)` / `make_consumer(settings, group, topics)` building `confluent_kafka` clients with `security.protocol=SASL_SSL`, `sasl.mechanism=SCRAM-SHA-512`, the CA file, `enable.auto.commit=false`; a `Publisher` protocol so tests inject a recording fake. cards-authorization publishes one `card.authorized` JSON event per `/work` tick (`{"txn_id", "amount", "currency": "EUR", "result", "ts"}`); fraud-scoring runs a consumer thread on `card.authorized`, scores each event (same distribution logic as M6a, so the drift fault still works), publishes `fraud.scored`, commits after publish; open-banking-api consumes `fraud.scored` and counts `openbanking_events_consumed_total`. Metrics: `kafka_events_produced_total{topic}`, `kafka_events_consumed_total{topic}`, `kafka_produce_errors_total`. Without Kafka settings the services behave exactly as in M6a (ticker only).
4. Faults: fraud-scoring `lag` = the consumer thread pauses polling (stays alive, `/healthz` stays 200) so `kafka_consumergroup_lag{consumergroup="fraud-scoring"}` grows; clearing resumes. `broker-down` is a chaos *action*, not a service mode: `scripts/chaos_k8s.py kafka broker-down` scales the `KafkaNodePool` to 0 replicas (`kubectl -n bank patch kafkanodepool <name> --type merge -p '{"spec":{"replicas":0}}'`), `kafka clear` sets it back to 1 and waits for the broker pod Ready; `bankops chaos --estate kubernetes kafka --mode broker-down|--clear` goes through the same script. Add `kafka` to the shared fault table with the single mode `broker-down`.
5. `task estate-up` waits for the `Kafka` resource's `Ready` condition (10-minute budget, prints the operator log tail on timeout); `task estate-status` also prints topics (`kubectl get kafkatopics -n bank`) and consumer-group lag from the kafka-exporter metrics (`curl` the exporter Service through `kubectl port-forward`-free NodePort? no - use `kubectl exec` into the broker with `bin/kafka-consumer-groups.sh --describe --all-groups` and the SCRAM admin credentials from a `KafkaUser` `admin` with `superUser` rights that only `estate-status` uses); `scripts/estate_status.py` gains `--kafka`.
6. CI: `helm` job renders with `kafka.enabled=true` and `false`; kubeconform gets the Strimzi CRD schemas from the datreeio CRDs-catalog (pinned commit); new `contract` job (`ubuntu-latest`, Docker available) runs `pytest tests/contract -m contract`.
7. Tests, `tests/bank/k8s/`: `KafkaSettings.from_env` (unset -> None; set -> client config with SASL_SSL/SCRAM and CA path), each service's publish/consume behaviour with the fake publisher/consumer (event shapes, commit-after-publish, `lag` pauses polling and health stays 200), `chaos_k8s.py kafka broker-down|clear` (kubectl monkeypatched, right patch body), `estate_status.py --kafka` parsing. `tests/contract/` (skipped without Docker): Redpanda via testcontainers - cards-authorization's publisher produces a real `card.authorized` event, fraud-scoring's consumer receives it and produces `fraud.scored`, open-banking-api's consumer receives that; a `lag` toggle stops consumption and the group lag reported by Redpanda's admin API (or `rpk`) grows.
8. Docs: `deploy/helm/nordwind-bank/README.md` Kafka section (values, users/ACLs table, how to tail a topic with `kubectl exec ... kafka-console-consumer.sh`), `docs/runbooks/kubernetes-estate.md` Kafka section (broker-down recovery, lag inspection), `docs/DESIGN.md` section 3: `lag` and `broker-down` marked live from M7a; C4 waits for M7b (bridge + relay change the picture); README row M7 "M7a wiring merged".

## Non-requirements

`alerts-bridge`, `kafka-relay`, route A, Alertmanager routing changes, Kafka alert rules, the `fraud-lag` / `broker-down` scenarios in `estate_scenarios.py` (all M7b); Kafka Connect, Schema Registry, mTLS client certs, multi-broker, AKS/MSK.
