# Spec: M6b - the kind cluster, `task estate-up/down/status/chaos-k8s`, `estate-demo.yml` v1 (cards-timeouts scenario), the Kubernetes runbook, C4 for the estate

Slice 2 of 2 of `docs/specs/m6-kind-estate.md`. Builds on M6a (`bank/k8s/*` services + Dockerfiles, `deploy/helm/nordwind-bank`, `deploy/helm/values/kube-prometheus-stack.yaml` with the `__FORWARDER_URL__` placeholder and `scripts/render_alertmanager_values.py`), M5b (the forwarder function URL is the `infra/azure` output `forwarder_url`, sensitive), M4/#35 (`scripts/chaos_probe.py` and its `wait_for_alert` / `wait_for_verdict` helpers; the console API token in SSM), and the repository's Taskfile. Repository conventions unchanged; all offline gates must pass; the new live gate is `estate-demo.yml` itself. Cost: $0 (kind on the laptop or on `ubuntu-latest`; ~15 GitHub-minutes per demo run).

## Requirements

1. `deploy/kind/cluster.yaml`: one control-plane node, node image pinned to a Kubernetes 1.31 kindest/node digest, `extraPortMappings` 9090 -> 30090 and 9093 -> 30093 (NodePort Services for Prometheus and Alertmanager are added through the kube-prometheus-stack values: `prometheus.service.type: NodePort` / `nodePort: 30090`, same for Alertmanager 30093) so `http://localhost:9090` and `http://localhost:9093` work without port-forwards.
2. `Taskfile.yml` tasks (all idempotent, all with a one-line `desc`; pinned versions in `vars:` - kind node image, kube-prometheus-stack chart version, kubeconform, trivy):
   - `estate-up`: `kind create cluster --name nordwind --config deploy/kind/cluster.yaml` if the cluster does not exist; `helm repo add prometheus-community` + `update`; render the Alertmanager values with `FORWARDER_URL` (env var; empty allowed - route B then goes to the dummy receiver and `estate-status` says so); `helm upgrade --install monitoring prometheus-community/kube-prometheus-stack --version <pinned> -n monitoring --create-namespace -f <rendered values> --wait`; build the three images tagged `nordwind/<service>:dev` and `kind load docker-image` them; `helm upgrade --install nordwind-bank deploy/helm/nordwind-bank -n bank --create-namespace --set imageTag=dev --wait --timeout 5m`; print the UIs and `kubectl get pods -A`.
   - `estate-down`: `kind delete cluster --name nordwind`.
   - `estate-status`: pods in `bank` and `monitoring`, the faults ConfigMap contents, firing alerts from `http://localhost:9093/api/v2/alerts?active=true` (name, service, severity, startsAt) via a small stdlib script `scripts/estate_status.py`.
   - `chaos-k8s -- <service> <mode|clear>`: `kubectl -n bank patch configmap nordwind-faults --type merge -p '{"data":{"<service>":"<mode>"}}'` (`clear` writes `""`); validates the service/mode pair against the same table `bankops chaos` uses (share the table: move `VALID_MODES` to `bank/faults.py` importable by both if it is not already shared).
   - `helm-lint`, `helm-check` already exist from M6a; add `estate-demo` (runs `scripts/estate_scenarios.py --scenario cards-timeouts` against the local cluster).
3. `scripts/estate_scenarios.py` (stdlib; reuses `scripts/chaos_probe.py` helpers by import): `--scenario cards-timeouts` = set fault `timeouts` on `cards-authorization` through the ConfigMap (`kubectl` via `subprocess`, injectable), wait until Alertmanager (`--alertmanager http://localhost:9093`) shows `CardsAuthHighLatency` firing (budget `--alert-timeout`, default 480 s), then wait until the console API (`API_BASE`, `SMOKE_TOKEN`) lists an alert with `estate == "kubernetes"`, `service == "cards-authorization"`, `alert_name == "CardsAuthHighLatency"` received after the scenario started and with a verdict (budget `--verdict-timeout`, default 600 s), print the verdict, clear the fault in a `finally`. Exit 1 on any timeout with a message saying which hop failed (rule never fired / Alertmanager never delivered / no verdict). `--scenario list` prints the scenarios (`fraud-lag`, `broker-down` are registered as "M7" and exit 2 if requested).
4. `.github/workflows/estate-demo.yml`: `workflow_dispatch` + `schedule: "0 6 * * 0"`; one job on `ubuntu-latest`, `timeout-minutes: 25`, `environment: demo` (for the secrets), `concurrency: estate-demo` without cancel-in-progress; steps: checkout, install task / kind / helm / kubeconform (pinned, `engineerd/setup-kind` or direct download with checksums), `task estate-up` with `FORWARDER_URL` from the environment secret `FORWARDER_URL` (document that it is set from `terraform output -raw forwarder_url` of `infra/azure`), AWS OIDC role -> read `SMOKE_TOKEN` from SSM exactly as the smoke job does, `task estate-demo`, then `if: always()`: `kubectl -n monitoring` dump of Alertmanager alerts (`/api/v2/alerts` via `kubectl exec`/port-forward-free NodePort), Prometheus rules state (`/api/v1/rules`), `kubectl -n bank logs` for the three services, `kubectl get events -A --sort-by=.lastTimestamp | tail -100`, uploaded as the artifact `estate-demo-<run id>`; finally `task estate-down`. Add the scheduled run's status badge to the README.
5. `cli/bankops`: `chaos --estate kubernetes <service> --mode <m>|--clear` shells out to the same `kubectl patch` (`subprocess.run`, monkeypatched in tests); default estate stays `aws` (console route). `bankops chaos --status` unchanged (AWS only) but prints a hint line for Kubernetes.
6. Tests: `tests/scripts/test_estate_scenarios.py` (kubectl and HTTP monkeypatched: happy path, rule-never-fires timeout, no-verdict timeout, fault cleared on failure, `list`), `tests/scripts/test_estate_status.py`, `tests/cli/bankops` for `--estate kubernetes` (command line built correctly, validation of modes), Taskfile YAML validity test (`task --list` in CI via the `helm` job).
7. Docs and diagrams: `docs/c4/workspace.dsl` - `kubernetesEstate` containers `cards-authorization`, `fraud-scoring`, `open-banking-api`, `prometheus`, `alertmanager` (Kafka containers wait for M7), relationships `prometheus -> services "scrape"`, `alertmanager -> forwarder "route B webhook"`, and a `deploymentEnvironment "kind"` with two deployment nodes (Laptop / GitHub Actions runner) each containing the kind node and container instances; regenerate exports. `docs/runbooks/kubernetes-estate.md`: prerequisites (Docker Desktop ~6 GB, kind/helm/task versions), `task estate-up` walkthrough with expected output, the UIs, the chaos cookbook for the six M6a rules with expected time-to-verdict (~6-9 min), how to read `estate-demo` artifacts, teardown. `docs/DESIGN.md` section 3: the three services "deployed by M6 (kind)"; README roadmap row M6 + badge; `infra/README.md` gets a pointer (Kubernetes is not Terraform-managed by design - D7).

## Non-requirements

Kafka/Strimzi and route A (M7), Grafana, AKS, Ingress/TLS, multi-node kind, running the demo on every PR.
