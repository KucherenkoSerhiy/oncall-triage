# Spec: M9e - runbooks (spine, deploy and rollback with a recorded drill, secrets rotation, cost), the README demo script and reviewer guide

Slice 5 of 5 of `docs/specs/m9-hardening.md` (requirements 6 and 7). Builds on everything shipped so far - read the issues and PRs of M4-M7 (#18, #20, #22, #24 and the fix PRs they reference) because the runbooks must describe the failure modes that actually happened, not hypothetical ones. Repository conventions unchanged; this slice is documentation plus one small script, so the offline gate is: every link in the new documents resolves (`scripts/check_links.py`, stdlib, run by CI's python job), Markdown renders, and the recorded drill is real (its run links exist).

## Requirements

1. `docs/runbooks/triage-spine.md` - symptom-first sections, each with "what you see" (console / smoke / diagnose output), "first check" (the exact `gh workflow run diagnose.yml` invocation and which section to read), "likely causes" (drawn from the real incidents: dedup collision #38 / #71, alarm topic KMS #47, floats in alarm payloads #50, forwarder without content #64, adapter service naming #66), "fix" and "verify": ingest 5xx / 422s, queue backing up, DLQ depth alarm (`bankops replay-dlq` from M9b), worker cap reached, verdicts missing, an estate's alert never arriving (per estate: CloudWatch alarm -> SNS; Azure Monitor -> action group -> forwarder; Alertmanager -> route A relay / route B forwarder), console 401s (token rotation).
2. `docs/runbooks/deploy-and-rollback.md` - how a change flows (PR plan comment -> approve twice -> apply -> smoke -> optional chaos probe), the concurrency group and why a dispatch can queue, the two approval legs, what the `Verify the Function apps` step guards, and the **rollback drill**: redeploy the previous worker image with `gh workflow run deploy.yml -f root=aws -f worker_image_sha=sha-<previous>`, verify with `bankops fire` + the console, then roll forward - executed once for real as part of this slice and recorded with timestamps, run links and the before/after `CodeSha256` from `diagnose.yml` (a table in the runbook, not a promise).
3. `docs/runbooks/secrets-rotation.md` - one section per secret with owner, where it lives, what reads it, rotation steps, what breaks in between, and the order: console token (SSM; console users, `bankops`, the notifications Function's `CONSOLE_TOKEN` app setting -> needs an Azure redeploy; the `chaos_probe` reads it fresh), ingest HMAC secret (SSM; smoke, forwarder app setting, kafka-relay Kubernetes Secret -> rotate producers before the verifier or accept a short window - spell out the choice), Anthropic API key (repository secret -> the `anthropic_key` job syncs it to SSM on the next deploy), Cloudflare API token (repository secret; only the DNS delegation plan/apply uses it), forwarder function key (regenerate in Azure -> `FORWARDER_URL` environment secret -> next estate-demo). Include the "token appeared in a screenshot" case (#31) as the worked example and actually rotate the console token as part of this slice (record the run).
4. `docs/runbooks/cost.md` - where each dollar goes (the table from DESIGN section 8 refreshed with the first real month: AWS Cost Explorer and Azure Cost Management screenshots are not required, numbers are), the two budgets and their e-mails, what the always-free tiers cover, what to destroy first if the budget alarm fires (`estate-demo` schedule, then Azure Functions, then the bank Lambdas' schedules), and the "one month later" checklist.
5. README: a "5-minute demo" script at the top of the roadmap - open the console, `bankops chaos payments --mode pool`, watch the known-issue verdict; `estate-demo.yml` for the Kubernetes story ("one verdict arrived over Kafka, the one about Kafka did not"); `chaos_probe=notifications-429` for Azure - each with the expected time-to-verdict and a link to the recorded probe; a "What a reviewer should look at" list (tests + contract tests, the C4 drift gate, runbooks, ADR index, the issues-per-slice tracking, the cost table); the cost table with actuals; and the architecture picture links (generated C4 views). Keep the README under ~250 lines - move detail into `docs/`.
6. `scripts/check_links.py`: walks `README.md`, `docs/**/*.md`, `infra/README.md`, `bank/**/README.md` and fails on relative links that do not resolve and on `docs/c4/generated` images/views that are not referenced from any document (drift the other way); unit-tested with a temp tree; wired into the python CI job and `task docs-check`.
7. ADR 0016 "Runbooks derived from incidents" (short: every runbook section cites the issue that motivated it; new incidents add a section before they close). ADR index regenerated. README roadmap row M9 -> done when M9a-e are merged; the milestone table's live-probe column filled for every milestone.

## Non-requirements

New infrastructure, PagerDuty/Slack, SSO, anything the other M9 slices own.
