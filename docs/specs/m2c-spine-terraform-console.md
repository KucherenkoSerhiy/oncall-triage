# Spec: M2c - the alert spine in Terraform, the static console, the smoke probe

Builds on M2a (`services/ingest`) and M2b (`services/console_api`, `services/triage_worker`, `cli/bankops`). Terraform lives in `infra/aws` (root module already applied by CI: budget + Route 53 zone `triage.serhiykucherenko.dev`, plus the Cloudflare delegation). Offline gates that must pass: `terraform fmt -check -recursive infra`, `terraform -chdir=infra/aws init -backend=false && terraform -chdir=infra/aws validate`, `tflint --chdir=infra/aws --config=<repo>/.tflint.hcl` (binary at `C:/tools/tflint/tflint.exe`), `checkov --config-file .checkov.yaml` (every skip inline with a reason), `ruff`/`mypy`/`pytest` for the Python parts. Provider constraint for AWS is already `>= 5.90, < 7.0`; add `hashicorp/archive` and `hashicorp/random` with sane ranges. Region is `var.region` = `eu-north-1`; CloudFront certificates must come from a `us-east-1` provider alias (`provider "aws" { alias = "us_east_1" region = "us-east-1" }` with the same default tags).

## Requirements

1. Layout inside `infra/aws`: `locals.tf` (name prefix, common tags incl. `c4_container`), `data.tf` (the workload permissions boundary policy looked up by name `${var.project}-${var.environment}-workload-boundary`, current account/region), `storage.tf` (DynamoDB), `messaging.tf` (SQS + DLQ, SNS), `lambdas.tf` (packaging + three functions + roles + event sources), `api.tf` (HTTP API, routes, integrations, custom domain), `console.tf` (S3, CloudFront, certificate, records, objects), `secrets.tf` (SSM), `outputs.tf` additions. Keep `main.tf` for provider + budget + zone as it is.
2. DynamoDB (all `PAY_PER_REQUEST` is NOT allowed - use `PROVISIONED` with 5 read / 5 write units to stay in the always-free tier; point-in-time recovery on; SSE default): `alerts` (hash `alert_id`; GSIs `by_fingerprint` hash `fingerprint` range `received_at`, `by_status` hash `status` range `received_at`, both `ALL` projection, 2/2 units each); `verdicts` (hash `alert_id`); `known_issues` (hash `service`, range `issue_id`). Names `${local.name_prefix}-alerts|verdicts|known-issues`. Tag `c4_container = "store"`.
3. SQS: queue `${local.name_prefix}-alerts` (visibility 90 s, SSE-SQS) with a dead-letter queue (`maxReceiveCount` 3, retention 14 days). SNS topic `${local.name_prefix}-alarms` (tag `c4_container = "alarms"`) subscribed to the ingest Lambda with the matching `aws_lambda_permission`. Tags `c4_container = "queue"`.
4. Lambdas (runtime `python3.12`, arm64, 30 s timeout, 256 MB except the worker at 512 MB / 60 s): `ingest`, `console-api`, `triage-worker`. Package with `archive_file` zips built from a staging directory the module assembles via `null_resource`-free means: `data "archive_file"` with `source_dir = "${path.module}/../../services"` and `excludes` for tests, caches and READMEs, plus `cli/` excluded - one zip shared by the three functions is acceptable (handler paths `services.ingest.handler.lambda_handler`, `services.console_api.handler.lambda_handler`, `services.triage_worker.handler.lambda_handler`). Each function has its own IAM role named `${var.project}-${var.environment}-<fn>` with `permissions_boundary` = the looked-up boundary ARN, an inline policy scoped to exactly its tables/queue/parameters (ingest: PutItem/UpdateItem/Query on alerts, SendMessage on the queue, GetParameter on the HMAC secret; console-api: Query/GetItem/PutItem/DeleteItem on the three tables, GetParameter on the console token; worker: GetItem/UpdateItem on alerts, PutItem on verdicts, SQS receive/delete/change-visibility) and `AWSLambdaBasicExecutionRole`. Environment variables exactly as the Python expects (`ALERTS_TABLE`, `VERDICTS_TABLE`, `KNOWN_ISSUES_TABLE`, `ALERTS_QUEUE_URL`, `INGEST_HMAC_SECRET`, `CONSOLE_TOKEN`, `CONSOLE_ORIGIN`); the two secrets are read from SSM at deploy time via `data.aws_ssm_parameter` (values generated in this root - see 7 - so no plaintext lands in the repo; they do land in Lambda configuration, which is the accepted v1 trade-off and must be stated in a comment). Worker event source mapping from the queue, batch size 5, `function_response_types = ["ReportBatchItemFailures"]`. Log groups created explicitly with 14-day retention. Tags `c4_container` = `ingest` / `api` / `worker`.
5. HTTP API (`aws_apigatewayv2_api`, protocol HTTP, CORS handled by the Lambda): routes `POST /alerts` -> ingest; `GET /health`, `GET /alerts`, `GET /alerts/{alert_id}`, `GET /known-issues`, `POST /known-issues`, `DELETE /known-issues/{service}/{issue_id}`, `OPTIONS /{proxy+}` -> console-api. Default stage with auto-deploy, access logs to a log group (14 days), throttling 10 rps burst 20. Custom domain `api.${var.domain}` with an ACM certificate in `var.region` validated by DNS records in the zone, API mapping, and a Route 53 A alias. Tag `c4_container = "api"`.
6. Console: private S3 bucket `${local.name_prefix}-console` (public access blocked, versioning on, SSE-S3), CloudFront distribution with Origin Access Control, default root `index.html`, HTTPS only, price class 100, aliases `[var.domain]`, ACM certificate from the `us_east_1` alias validated in the zone; Route 53 A and AAAA aliases for the apex `var.domain`; `aws_s3_object` for every file under `console/` with `etag = filemd5(...)` and correct `content_type` (html/js/css/json). Tag `c4_container = "console"`.
7. Secrets: `random_password` for the HMAC secret (48 chars) and the console token (32 chars, no special characters); stored as SSM `SecureString` parameters `/${var.project}/${var.environment}/ingest-hmac-secret` and `/${var.project}/${var.environment}/console-token` (KMS default key). Outputs `console_token_parameter` and `hmac_secret_parameter` (names, not values), `api_url`, `console_url`, `alarms_topic_arn`, `alerts_queue_url`.
8. `console/` static site, no build step, vanilla JS, three files: `index.html`, `app.js`, `styles.css`. Behaviour: on first load prompt for the bearer token (stored in `localStorage`), then poll `GET /alerts?limit=50` every 10 s; render a table (time, severity chip coloured by sev1..sev4, service, alert name, status, occurrences, verdict action + text) with an inline "teach" form per row (pre-filled service; pattern + explanation; `POST /known-issues`); a second panel lists known issues per service with delete; the API base is read from a `<meta name="api-base">` tag written by Terraform? No - keep it static: `app.js` derives it as `https://api.` + `location.hostname` when served from the custom domain, and falls back to `localStorage.apiBase` (settable via `?api=` query parameter) for local use. Dark/light via `prefers-color-scheme`. Semantic HTML with labels; no framework, no CDN.
9. `scripts/smoke.py` (stdlib only, used by `deploy.yml`'s smoke step - make that step call it): reads `API_BASE` (default `https://api.triage.serhiykucherenko.dev`), `SMOKE_HMAC_SECRET`, `SMOKE_TOKEN` from the environment (the workflow step must read the two parameters with `aws ssm get-parameter --with-decryption` using the deploy role and export them for the step); GETs `/health`; fires one `bankops` alert (`service=smoke`, `alert_name=SmokeTest`, `sev4`) signed with `services.ingest.hmac_auth.sign`; polls `GET /alerts/{alert_id}` up to 90 s until a verdict exists; exits 0 with a one-line summary, non-zero with the failing step named. A unit test covers its polling logic with the HTTP function monkeypatched.
10. Docs and diagram: `docs/c4/workspace.dsl` deployment view must list the new nodes only if missing (Lambda, SQS, SNS, DynamoDB, CloudFront + S3, SSM, CloudWatch already exist as deployment nodes - add `API Gateway` for `triage.api` if it is not there); regenerate with the documented Docker command + `python scripts/c4_render.py`. `infra/README.md`: a section "What `infra/aws` deploys" listing the components and the two SSM parameters an operator reads to use `bankops` (`aws ssm get-parameter --with-decryption --name ...`). Every new resource carries `c4_container`.

## Non-requirements

The real ADK worker (M3), the AWS bank services and alarms (M4), Azure resources, Kubernetes, DNSSEC/query logging (M9), Cognito, WAF, custom CloudFront functions, any `terraform plan` against real credentials (CI does that on the PR).
