# Spec: M2a - alert ingest (canonical alert, HMAC, PII scrubber, dedup, source adapters, Lambda handler)

Repository conventions (already configured, do not change): Python 3.12, `ruff` (config in pyproject.toml, line length 100, rules E/F/I/B/UP/N/S/SIM/RUF), `mypy` (add the new package to `[tool.mypy] packages`), `pytest` (testpaths is `tests`). Run `ruff check .`, `ruff format --check .`, `mypy`, `pytest` before declaring done; all must pass. The existing package `oncall_triage/` and its tests must keep passing untouched. New runtime dependency allowed: `boto3`. New dev dependencies allowed: `moto[dynamodb,sqs]>=5` and, optionally, `boto3-stubs[dynamodb,sqs]`. Add them to `requirements.txt` / `requirements-dev.txt` respectively. No other third-party packages (no pydantic, no requests).

## Requirements

1. Package `services/ingest/` importable as `services.ingest` (add `services/__init__.py` and `services/ingest/__init__.py`) with these modules: `canonical.py`, `hmac_auth.py`, `scrub.py`, `dedup.py`, `adapters/__init__.py`, `adapters/bankops.py`, `adapters/cloudwatch.py`, `adapters/alertmanager.py`, `adapters/azure_monitor.py`, `handler.py`.
2. `canonical.py`: a frozen dataclass `CanonicalAlert` with fields exactly: `alert_id: str` (26-character Crockford-base32 ULID built from milliseconds + randomness by `new_alert_id()`), `fingerprint: str`, `source: str` (one of `cloudwatch`, `azure-monitor`, `alertmanager`, `bankops`), `estate: str` (`aws`, `azure`, `kubernetes`), `service: str`, `alert_name: str`, `severity: str` (`sev1`..`sev4`), `title: str`, `description: str`, `sample_logs: tuple[str, ...]`, `labels: dict[str, str]`, `fired_at: str` (RFC 3339 UTC), `received_at: str` (RFC 3339 UTC), `raw: dict`. Provide `to_item() -> dict` (DynamoDB-ready, JSON-serialisable) and `from_item(item) -> CanonicalAlert`. `compute_fingerprint(source, service, alert_name, labels)` is the sha256 hex digest of `source|service|alert_name|k1=v1,k2=v2,...` with labels sorted by key, EXCLUDING the labels `route` and `runbook` and any label whose name starts with `_`. Validation raises `ValueError` naming the offending field for an unknown source, estate or severity, or an empty service, alert_name or title.
3. `hmac_auth.py`: `sign(secret: bytes, timestamp: str, body: bytes) -> str` returns `sha256=<hex>` of HMAC-SHA256 over `timestamp.encode() + b"." + body`. `verify(secret, timestamp, body, signature, now: float | None = None, max_skew_seconds: int = 300) -> None` raises `HmacError` (a `ValueError` subclass) when the timestamp is not integer epoch seconds, when the skew exceeds the window in either direction, when the signature is missing or malformed, or when it does not match (compare with `hmac.compare_digest`).
4. `scrub.py`: `scrub_text(text: str) -> str` replaces card numbers (runs of 13-19 digits that may contain single spaces or dashes between groups and that pass the Luhn check) with `[REDACTED:PAN]`, IBANs (2 letters, 2 digits, 11-30 alphanumerics, optional spaces) with `[REDACTED:IBAN]`, and e-mail addresses with `[REDACTED:EMAIL]`. Digit runs that fail Luhn (for example 1234567890123) must be left untouched. `scrub_alert(alert) -> CanonicalAlert` scrubs `title`, `description`, every `sample_logs` entry, every label value, and every string value found recursively inside `raw` (dicts and lists at any depth).
5. `dedup.py`: `class AlertStore` wrapping a DynamoDB table (boto3 resource; table name given to the constructor). `put_new(alert)` writes the item with `status="queued"` and `occurrences=1`. `find_open(fingerprint, now_iso) -> dict | None` returns the most recent item with that fingerprint whose `status` is `queued` or `triaged` and whose `received_at` lies within the last 30 minutes, queried through a GSI named `by_fingerprint` (partition key `fingerprint`, sort key `received_at`). `bump(alert_id, now_iso)` increments `occurrences` atomically (UpdateExpression `ADD`) and sets `last_seen_at`. Document the table and GSI schema in the module docstring (Terraform comes in a later spec).
6. Adapters, each exposing `to_canonical(payload: dict, received_at: str) -> CanonicalAlert` (define `class NotAnAlert(Exception)` in `adapters/__init__.py`):
   - `bankops`: the payload is already canonical minus `alert_id`, `fingerprint` and `received_at`; validate it and fill those three.
   - `cloudwatch`: the payload is the JSON of an SNS CloudWatch alarm state-change message (`AlarmName`, `AlarmDescription`, `NewStateValue`, `NewStateReason`, `StateChangeTime`, `Trigger.MetricName`, `Trigger.Dimensions[]` with `name`/`value`). Only `NewStateValue == "ALARM"` produces an alert; `OK` and `INSUFFICIENT_DATA` raise `NotAnAlert`. `service` is the value after `service=` inside `AlarmDescription` if present, else the value of the first dimension named `FunctionName`, `QueueName` or `TopicName` with a leading `nordwind-triage-demo-` stripped, else `unknown`. `severity` is `sev1` if the alarm name contains `Sev1`, `sev2` if it contains `Sev2`, else `sev3`. `estate="aws"`, `alert_name=AlarmName`, `title=AlarmName + ": " + NewStateReason`.
   - `alertmanager`: the payload is an Alertmanager webhook (`receiver`, `alerts[]` each with `status`, `labels`, `annotations`, `startsAt`). Provide `to_canonical_many(payload, received_at) -> list[CanonicalAlert]` returning one alert per entry whose `status == "firing"` (and `to_canonical` returning the first of them or raising `NotAnAlert` when there is none). `service` = label `service`, falling back to `job`, then `unknown`; `alert_name` = label `alertname`; `severity` from label `severity`: critical -> sev1, high -> sev2, warning -> sev3, anything else -> sev4; `estate="kubernetes"`; `title` = annotation `summary` or the alert name; `description` = annotation `description` or empty; `labels["route"]` = `"A"` when `receiver` contains `kafka`, else `"B"`.
   - `azure_monitor`: the payload is the Azure Monitor common alert schema (`data.essentials.alertRule`, `.severity`, `.firedDateTime`, `.monitorCondition`, `.description`, `.alertTargetIDs[]`; `data.alertContext` kept in `raw`). Only `monitorCondition == "Fired"` produces an alert, otherwise `NotAnAlert`. `severity`: Sev0 and Sev1 -> sev1, Sev2 -> sev2, Sev3 -> sev3, Sev4 -> sev4. `service` is the last path segment of the first target id, lowercased, with a leading `nordwind-triage-demo-` stripped. `estate="azure"`, `alert_name=alertRule`.
7. `handler.py`: `lambda_handler(event, context)` supporting two event shapes. (a) API Gateway HTTP API v2 `POST /alerts` with headers `x-nordwind-timestamp` and `x-nordwind-signature` and a JSON body `{"source": "<adapter name>", "payload": {...}}`: verify the HMAC with the secret from `os.environ["INGEST_HMAC_SECRET"]` (UTF-8 bytes) over the raw body; respond 401 `{"error": ...}` on `HmacError`, 400 on `ValueError`/malformed JSON, 422 on `NotAnAlert`. (b) An SNS event (`Records[].Sns.Message`), always source `cloudwatch`, no HMAC - the SNS subscription is the trust boundary. For every canonical alert: scrub it, then `find_open(fingerprint, received_at)`; if an open alert exists, `bump` it and report `deduped: true` without enqueueing; otherwise `put_new` and send `{"alert_id": ...}` to the SQS queue `os.environ["ALERTS_QUEUE_URL"]`. HTTP response 202 `{"results": [{"alert_id", "fingerprint", "deduped"}]}`; for SNS events return `{"results": [...]}` directly. Emit one structured JSON log line per alert through `logging` (`alert_id`, `source`, `service`, `deduped`). The table name comes from `os.environ["ALERTS_TABLE"]`. Create boto3 clients lazily so importing the module needs no AWS environment.
8. Tests under `tests/ingest/` (pytest; `moto`'s `mock_aws` for DynamoDB + SQS; a fixture creates the table with the GSI and the queue and sets the environment variables): canonical validation errors name the field; fingerprint is stable, ignores label order, and excludes `route`/`runbook`/`_x`; ULID is 26 chars and two ids generated 2 ms apart sort in time order; HMAC happy path, skew past and future, bad signature, malformed timestamp; scrubber corpus of at least eight strings (valid Visa, Mastercard and Amex test numbers written with spaces and with dashes, an invalid-Luhn 13-digit number that must survive, two IBANs, two e-mails, one log line mixing all three) plus the recursive `raw` case; dedup: first alert stored with status queued and one SQS message, an identical alert 5 minutes later bumps `occurrences` to 2 and sends nothing, an identical alert 31 minutes later is stored as new; every adapter with one realistic payload kept as `tests/ingest/fixtures/<adapter>.json`, including the CloudWatch `OK` and Azure `Resolved` `NotAnAlert` paths and the Alertmanager multi-alert case; handler: HTTP 202 happy path, 401 on a bad signature, 422 on a resolved alert, the SNS path stores and enqueues, the dedup path reports `deduped: true`.
9. `services/ingest/README.md` (30-60 lines): the two event shapes, the canonical alert fields, the HMAC header contract with a worked example (secret, timestamp, body, resulting header), the dedup rule, the environment variables, and how to run the tests.

## Non-requirements

Terraform, zip packaging, the console API, the triage worker, retries or DLQ handling, network calls beyond moto, async code, Kafka.
