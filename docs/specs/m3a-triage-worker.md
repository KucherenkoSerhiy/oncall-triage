# Spec: M3a - the real triage worker (ADK roles on Claude, DynamoDB tools, verdict contract, daily cap, container image)

Replaces the stub in `services/triage_worker/handler.py` (M2b) with the three-role ADK workflow from `oncall_triage/` (phase 1), running per alert inside the SQS-triggered Lambda. Repository conventions unchanged (Python 3.12, ruff / ruff format / mypy with packages listed in pyproject / pytest; all existing tests keep passing, adapted where this spec says so). Allowed new dependencies: `litellm` (runtime; ADK's `google.adk.models.lite_llm.LiteLlm` needs it) - add to `requirements.txt`. Tests must never call a model or the network: every model interaction goes through one seam that tests replace with a fake.

## Requirements

1. `oncall_triage/agent.py` keeps the three agents (`triage`, `researcher`, `reporter`) and their instructions, with these changes: the model is built by a new `oncall_triage/model.py` exposing `build_model()` that returns `LiteLlm(model=os.environ.get("TRIAGE_MODEL", "anthropic/claude-haiku-4-5-20251001"))`; `agent.py` calls it once at import. The triage instruction is updated to describe the new tools (below) instead of `get_logs`. The reporter instruction additionally requires the reply to END with a fenced block exactly like:
   ```verdict
   {"known": false, "severity": "sev2", "action": "page", "summary": "one line"}
   ```
   where `action` is one of `page`, `monitor`, `ack`, and `known` mirrors what triage found. `tests/test_wiring.py` is adapted: tool names become `get_alert`, `get_recent_alerts`, `check_known`, `remember_issue`; the model assertion checks `build_model()` returns a `LiteLlm` whose `model` string starts with `anthropic/` by default and honours `TRIAGE_MODEL`.
2. `oncall_triage/tools.py` becomes store-backed. Define in `oncall_triage/stores.py` a `KnownIssueStore` Protocol (`find_known(service, error_text) -> dict | None`, `add_known(service, pattern, explanation, taught_by) -> dict`, `list_known(service) -> list[dict]`) with two implementations: `JsonFileStore(path)` (the existing JSON file behaviour, matching by case-insensitive substring, now scoped by `service` with `"*"` meaning any service - the shipped `known_issues.json` entries get `"service": "*"`) and `DynamoStore(known_issues_table)` (the M2b table: hash `service`, range `issue_id`; `find_known` queries the alert's service AND `"*"`). An `AlertRepo` in the same module wraps the alerts table: `get_alert(alert_id) -> dict | None`, `recent_alerts(service, since_iso, limit=10) -> list[dict]` (via the `by_status` GSI for `queued` and `triaged`, filtered by service). `tools.py` exposes four plain functions bound to module-level store instances that `configure(known_store, alert_repo)` swaps at runtime: `get_alert(alert_id) -> dict` (the canonical item minus `raw`, plus `occurrences`), `get_recent_alerts(service, minutes=30) -> list[dict]` (id, alert_name, severity, received_at, status), `check_known(service, error_text) -> dict` (`known`, `pattern`, `explanation`), `remember_issue(service, error_pattern, explanation) -> dict`. Default configuration: `JsonFileStore` on `TRIAGE_STORE_PATH` (as today) and an `AlertRepo` over an in-memory dict, so `adk web` keeps working locally without AWS.
3. `services/triage_worker/runner.py`: `class TriageRunner` with `run(alert: dict) -> TriageResult` that builds an ADK `Runner` (`InMemorySessionService`, app name `nordwind-triage`, one fresh session per alert), sends the user message `Triage alert <alert_id>: <title>` and collects the final text; `TriageResult` = `text`, `verdict` (parsed from the trailing fenced `verdict` block; if absent or invalid JSON, fall back to `{"known": false, "severity": alert severity, "action": "monitor", "summary": "<first 200 chars>"}` and set `verdict_parse_error=True`), `model` (the model string), `prompt_hash` (sha256 of the three agents' instruction strings concatenated), `usage` (input/output token counts summed from ADK events when present, else zeros). The model seam: `TriageRunner(agent_factory=...)` defaults to the real root agent; tests pass a factory returning a scripted agent (an ADK `Agent` whose model is a tiny fake `BaseLlm` subclass replaying canned responses) - document that pattern in a test helper `tests/triage_worker/fake_llm.py`.
4. `services/triage_worker/handler.py`: per SQS record, load the alert (missing -> failure item), consult the daily cap (below), run `TriageRunner`, write the verdict item `{alert_id (pk), known, severity, action, summary, text, model, prompt_hash, input_tokens, output_tokens, verdict_parse_error, created_at}` with the same conditional put as the stub (redelivery is a no-op), set the alert `status` to `triaged`, log one JSON line (`alert_id`, `known`, `action`, `input_tokens`, `output_tokens`, `duration_ms`). Keep `ReportBatchItemFailures`. Configure the tools with `DynamoStore(KNOWN_ISSUES_TABLE)` and `AlertRepo(ALERTS_TABLE)` at cold start. Environment: `ALERTS_TABLE`, `VERDICTS_TABLE`, `KNOWN_ISSUES_TABLE`, `ANTHROPIC_API_KEY` (LiteLLM reads it), `TRIAGE_MODEL` (optional), `DAILY_ALERT_CAP` (default 500).
5. Daily cap: `services/triage_worker/cap.py` with `DailyCap(verdicts_table)` using items keyed `alert_id = "cap#YYYY-MM-DD"` in the verdicts table: `try_acquire(today) -> bool` does an atomic `ADD count :one` with a condition `attribute_not_exists(count) OR count < :cap`; when the condition fails the handler writes a verdict with `action="monitor"`, `summary="Daily LLM cap reached; not triaged"`, `model="cap"` and still marks the alert `triaged` (the console shows it plainly). Tests prove the 501st call in a day is capped and a new day resets.
6. Container image: `services/triage_worker/Dockerfile` on `public.ecr.aws/lambda/python:3.12` (arm64), installing `requirements.txt` and copying `oncall_triage/`, `services/ingest/`, `services/triage_worker/`; `CMD ["services.triage_worker.handler.lambda_handler"]`. Add `.dockerignore` (tests, caches, docs, infra, console, cli). `task worker:build` builds it locally; a `task worker:local` runs it with the Lambda runtime interface emulator and the handler test event `tests/triage_worker/fixtures/sqs_event.json` (document both in `services/triage_worker/README.md`). Do not push anywhere.
7. Tests (`tests/triage_worker/`, moto for DynamoDB): store implementations (JSON with `"*"` and per-service scoping; Dynamo `find_known` across service + `"*"`; `AlertRepo.recent_alerts`), tool functions after `configure`, verdict block parsing (valid, missing, malformed), `TriageRunner` with the fake LLM producing FORMAT A for a known alert and FORMAT B with a verdict block for a new one (assert the tools were actually called by inspecting the fake's recorded tool calls), handler happy path (verdict written, status triaged, tokens logged), redelivery no-op, cap behaviour, missing alert -> batch failure. The existing 14 wiring tests are adapted, not deleted.
8. Docs: `services/triage_worker/README.md` (40-80 lines: what runs per alert, the verdict contract, the cap, environment variables, the fake-LLM testing pattern, local container run); `docs/agent.md` gets a short "phase 2" note pointing at it; ADR 0004 gets an amendment paragraph stating the model seam (`build_model()` + `TRIAGE_MODEL`) and that no test ever calls a model.

## Non-requirements

Terraform for ECR / the image-based Lambda / the SSM parameter for the Anthropic key and the `deploy.yml` image build-and-push step (that is M3b), teach-from-console changes (M2b already covers the API), Slack or e-mail delivery, prompt tuning beyond the verdict block, streaming, any live model call in CI.
