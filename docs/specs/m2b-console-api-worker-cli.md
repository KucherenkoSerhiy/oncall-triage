# Spec: M2b - console API, stub triage worker, bankops CLI

Builds on M2a (`services/ingest`: `CanonicalAlert`, `to_item`/`from_item`, `AlertStore`, `hmac_auth.sign`). Reuse those modules; do not duplicate them. Repository conventions are unchanged: Python 3.12, `ruff` / `ruff format` / `mypy` (add new packages to `[tool.mypy] packages`) / `pytest` must all pass; existing tests must keep passing untouched. Allowed dependencies: `boto3` (runtime), `moto[dynamodb,sqs]>=5` (dev) - both already present after M2a. Nothing else (no requests, no click; use `argparse` and `urllib`).

## Requirements

1. `services/console_api/` (package `services.console_api`) with `handler.py`, `auth.py`, `store.py`, `http.py`.
   - `auth.py`: `check_bearer(headers: dict, expected_token: str) -> None` raises `AuthError` unless `Authorization: Bearer <token>` matches with `hmac.compare_digest`. Header lookup is case-insensitive.
   - `http.py`: helpers `json_response(status, body, origin)` returning an API Gateway HTTP API v2 response with `Content-Type: application/json` and CORS headers (`Access-Control-Allow-Origin` = the configured origin, `Access-Control-Allow-Headers: Authorization, Content-Type`, `Access-Control-Allow-Methods: GET, POST, DELETE, OPTIONS`); `OPTIONS` on any route returns 204 with the same headers and no auth.
   - `store.py`: `ConsoleStore(alerts_table, verdicts_table, known_issues_table)` over boto3 resources with: `list_alerts(limit=50) -> list[dict]` (query the alerts GSI `by_status` - partition key `status`, sort key `received_at` - for `queued` and `triaged`, merge, sort by `received_at` descending, cut to `limit`); `get_alert(alert_id) -> dict | None` returning the alert item plus `verdict` (item from the verdicts table, or `None`); `list_known_issues(service: str | None) -> list[dict]`; `add_known_issue(service, pattern, explanation, taught_by) -> dict` writing `{service (pk), issue_id (sk, ULID via services.ingest.canonical.new_alert_id), pattern, explanation, taught_by, created_at}`; `delete_known_issue(service, issue_id) -> bool`. Document all three table schemas (keys, GSIs) in the module docstring.
   - `handler.py`: `lambda_handler(event, context)` routing on `event["requestContext"]["http"]["method"]` + `event["rawPath"]`: `GET /health` (no auth, `{"ok": true}`); `GET /alerts?limit=`; `GET /alerts/{alert_id}` (404 if missing); `GET /known-issues?service=`; `POST /known-issues` (JSON body `{service, pattern, explanation}`, 400 on missing fields, 201 with the record; `taught_by` = `"console"`); `DELETE /known-issues/{service}/{issue_id}` (204 or 404). Every route except `/health` and `OPTIONS` requires the bearer token from `os.environ["CONSOLE_TOKEN"]` (401 on failure). Table names from `ALERTS_TABLE`, `VERDICTS_TABLE`, `KNOWN_ISSUES_TABLE`; origin from `CONSOLE_ORIGIN`. Unknown routes 404. Clients are created lazily.
2. `services/triage_worker/` (package `services.triage_worker`) with `handler.py`: an SQS-triggered `lambda_handler(event, context)` that, for each record `{"alert_id": ...}`, loads the alert, writes a verdict item `{alert_id (pk), known: false, severity: <alert severity>, action: "monitor", text: "Stub verdict (M2): triage worker arrives with M3.", model: "stub", prompt_hash: "", created_at}` with a conditional put (`attribute_not_exists(alert_id)`, so a redelivered message is a no-op) and sets the alert's `status` to `triaged`. Uses `ReportBatchItemFailures` semantics: return `{"batchItemFailures": [{"itemIdentifier": messageId}, ...]}` for records that raised, so SQS retries only those. Table names from `ALERTS_TABLE`, `VERDICTS_TABLE`.
3. `cli/bankops/` (package `cli.bankops`, entry `python -m cli.bankops`) with `__main__.py`, `client.py`, `commands.py`:
   - Configuration from environment with flags overriding: `BANKOPS_API` (base URL, e.g. `https://api.triage.serhiykucherenko.dev`), `BANKOPS_HMAC_SECRET`, `BANKOPS_TOKEN`.
   - `fire --service S --alert NAME [--severity sev1..sev4, default sev3] [--title T] [--description D] [--estate aws|azure|kubernetes, default aws] [--label k=v ...] [--log LINE ...]` builds a `bankops` payload (`source="bankops"`, `fired_at` = now UTC), signs it with `services.ingest.hmac_auth.sign` using the current epoch second as timestamp, POSTs `{"source": "bankops", "payload": ...}` to `/alerts` with the two `X-Nordwind-*` headers, prints the returned `alert_id` and `deduped` flag, exits 0 on 202, 1 otherwise with the error body.
   - `tail [--limit N] [--watch] [--interval 10]` GETs `/alerts` with the bearer token and prints a fixed-width table: received time (HH:MM:SS), severity, service, alert name, status, occurrences, verdict action (or `-`); `--watch` repeats every interval until Ctrl-C.
   - `teach --service S --pattern P --explanation E` POSTs `/known-issues`; `known [--service S]` lists them.
   - `client.py` wraps `urllib.request` with a 10 s timeout and raises `BankopsError(status, body)` on non-2xx; all HTTP goes through one function so tests can monkeypatch it.
4. Tests (pytest + moto, fixtures creating the three tables with the GSIs and the SQS queue): console API - 401 without/with a wrong token, `/health` open, `OPTIONS` 204 with CORS headers, `GET /alerts` ordering and limit across both statuses, `GET /alerts/{id}` with and without a verdict and 404, known-issues create/list/filter/delete round trip and 400 on a missing field; worker - a queued alert gets a verdict and becomes `triaged`, a redelivered message does not overwrite the verdict, a record for a missing alert appears in `batchItemFailures` while the others succeed; CLI - `fire` builds a correct payload and signature (assert by re-verifying with `hmac_auth.verify`), `tail` renders the table from a canned response, `teach` posts the right body, exit codes on error, all with the HTTP function monkeypatched (no network).
5. `docs/api.md` (40-80 lines): every console API route with method, auth, request and response examples, status codes, and the CORS behaviour; plus the `bankops` command reference.

## Non-requirements

Terraform, the static console page, the real ADK worker, pagination beyond `limit`, rate limiting, any network access in tests.
